# 脚本清单与拆解规范

## 1. 先判断值不值得脚本化

两条都满足才做：

1. 每篇重复 ≥ 3 次；
2. 输入和输出都能明确命名。

不满足就先写成规范条文，不要急着写脚本。一次性动作、规则还在变的动作，先别脚本化。

## 2. 按三类划边界

| 类别 | 允许做什么 | 禁止做什么 |
| --- | --- | --- |
| 只读检查 | 读文件、跑校验、出报告 | 改产物、写外部系统 |
| 产出构建 | 渲染、打包、生成预览 | 直接上传、直接发布 |
| 写入外部 | 写草稿箱、导台账 | 群发、改线上内容 |

一个脚本只干一类。混在一起就无法保证重跑安全。

## 3. 常用脚本清单

按需取用，不要一次全建。

### 3.1 取证类（只读 + 存档）

`research_fetch.py`

- 输入：选题、来源 URL 列表
- 输出：`source_manifest.json`、`pages/`、`images/`、`collection_leads`
- 关键约束：快照 + sha256；候选数字与已核验事实分离；不做判断
- 失败：单源失败记入清单，不阻断整体；全部失败则非零退出

`research_gate.py`

- 输入：研究包目录
- 输出：证据层错误码清单
- 检查：来源数量、工具证据（命令 + 退出码 + 输出文件 + 哈希）、模块覆盖、时效

### 3.2 结构类

`structure_gate.py`

- 输入：正文、结构契约
- 检查：单元顺序、必答问题、必备字段、数值或书面边界、首屏图位置、图片是否重复

### 3.3 呈现类

`visual_gate.py`

- 输入：图片目录、画像卡
- 检查：比例、越界、超框、压字、字号、托管方式
- 约束：所有阈值从画像卡读，不写死在代码里

### 3.4 合规类

`compliance_gate.py`

- 输入：正文、画像卡词表
- 检查：禁词、承诺性表述、诱导分享、资质敏感项

### 3.5 差异类

`delta_gate.py`

- 输入：当前稿、同选题上一版
- 检查：正文是否实质不同；完全相同即失败

### 3.6 编排类

`build_pipeline.py`

- 输入：选题、正文路径、研究包、封面
- 输出：成品目录 + 质量报告 JSON + 状态
- 约束：临时目录构建 → 门禁全过 → 原子平移 → 失败删临时目录

`publish_draft.py`

- 输入：质量报告 + 平台凭证
- 输出：草稿 + 状态 `UPLOADED`
- 约束：必须显式确认参数才执行；永不群发；写入失败不回跑门禁

### 3.7 复盘类

`analytics_import.py`

- 输入：后台导出表
- 输出：台账更新 + 复盘报告
- 约束：唯一键去重；占位符拦截；写库前备份；缺失字段标"资料不足"

`ledger_report.py`

- 输入：台账
- 输出：单篇诊断 + 分组对比 + 下一轮建议
- 约束：样本不足时只做单篇诊断，不做分组结论

## 4. 每个脚本必须写清的契约

```yaml
script: <名称>
purpose: <一句话>
inputs: <字段与路径>
outputs: <文件与状态>
idempotent: <重跑是否安全，如何保证>
atomic: <临时目录/原子平移/失败清理>
errors: <错误码与退出码>
not_do: <明确不做什么>
```

## 5. 上线前四问

| 问题 | 不合格 | 合格 |
| --- | --- | --- |
| 连跑两次结果一样吗 | 覆盖成半成品 | 输出带时间戳或固定幂等键 |
| 中途失败会留残稿吗 | 成品区出现缺图稿 | 临时目录构建，成功才平移 |
| 出错能定位到哪一步 | 只打印异常 | 独立错误码/退出码 |
| 输入缺失怎么办 | 静默跳过 | fail-fast，明确报错 |

## 6. 上线顺序

1. 只读检查类（门禁、审计）
2. 产出类（渲染、打包）
3. 写入类（草稿、台账）

写入类最后做，且必须已有稳定门禁。
